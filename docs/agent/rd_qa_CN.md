# 研发问答

## 规则实验要做因果 TimeSeriesSplit，或 Qlib 那种 CV 吗？

**不要。** 不是「规则不会过拟合所以偷懒」，是过拟合的通道不一样，本仓库已经用另一套闸门在挡。

TimeSeriesSplit 解决的是：模型在训练窗里调了几千个参数，会不会只记住那段路径。Qlib / `mlbot train` 的树、线性因子都要它——先用过去折拟合，再看后面折还在不在。

规则实验没有这步拟合。假设写死，三段各跑一遍，看的是**换一种市场结构还成不成**，不是「系数有没有记住训练集」。

## 规则参数少，拟合不了也记不住训练数据，是不是就不会过拟合？

**会过拟合，只是形态不同。** 规则几乎插值不了整段 K 线（记不住「2022-05-13 那天谁怎么走」）。它最多锁住 1～3 个门闩。门闩对了，像抓住一个粗结构；门闩是这段行情碰巧相关，换 regime 就废。

规则的过拟合是：扫阈值、换条件、看哪段顺眼就留。挡法是 Phase 1 不能结案 + 三段分列 Pareto（哪段坏就哪段否）+ kill switch OFF。

例子：BPC entry v2 压缩腿在 label 上好看，熊/牛还行，震荡年化翻脸 → reject。

## 把牛熊合成一跑，是不是比分段更好，也更像 TimeSeriesSplit？

**不要合成。** 合成会把坏段抹掉，看起来像「长期还行」。那正好是已写下的坑：非平稳时，更长的平均只会把已 drift 的规则洗干净。

三段是经济状态（熊 / 牛 / 震荡），不是把日历切成 K 折。TimeSeriesSplit 即使做了，早期折多半是熊、后期折多半是牛，仍然不如**显式**要求三段同号、MaxDD 不坏。

「做了更好」的是对照变体 × 三段摊在一张卡上，不是再切一刀 CV。

## 通过 IC 找出来的因子，为什么在模型或规则里，对未来可能还有预测性？

IC **不是**「模型记住了低维逻辑」。IC 只是说：在**这块面板、这个 label** 上，这个数和未来收益同向动过。

预测性（如果真有）来自：那个低维关系在**下一段还在**——经济含义没变、执行摩擦吃不完。不是因为它记住了训练数据。

也可能只是：
- 扫了几百个特征 × 一堆 τ，多重检验捞到的同号
- label（`forward_rr` / 成功标签）和生产目标（已实现路径、槽位、滑点、MaxDD）不是一回事
- 只在某一段市场结构里成立

本仓库用三段分列逼问的就是「下一段还在不在」。过了，才比较像抓住了结构；过不了，就是样本相关。

## 那它是记住了一些关键的低维空间决定性逻辑吗？

**有时是那个逻辑的影子，不是因为它记住了什么。**

「低维决定性逻辑」是你写下的**假设**（拥挤后回吐、超跌后均值回复、趋势里别在 chop 里开）。IC 只是这段样本里的相关，和假设长得一样。

- 门闩少、人能讲清、三段同号、MaxDD 不坏 → 比较像抓住了结构
- 只有 IC / 单窗 / 合成曲线 → 当它没记住、也没发现

Phase 1 永远不能 promote，就是把这句话写进流程。

## 模型和规则各防什么过拟合？什么时候才用 TimeSeriesSplit？

| | 模型 | 规则 |
|---|---|---|
| 容量 | 大，能记残差 | 小，记不住路径 |
| 过拟合形态 | 插值训练折 | 选错门闩 / 扫阈值 |
| 防护 | TimeSeriesSplit（别记折） | 三段 Pareto + 人能讲清机制 |
| IC 的角色 | 选特征的线索 | 同样只是线索，不是证据 |

只有以后真的在训可拟合模型（打分器、树、线性），才在 **train 内环**用 TimeSeriesSplit。结案仍看三段回测。不要把 Qlib CV 和法庭两套尺子叠在一起。

## 为什么 Phase 1（IC / label lift）不能结案？

目标函数不同。label 用 `forward_rr` 或成功标签；法庭用已实现路径上的年化 / Calmar / 胜率 / MaxDD / Sharpe，外加槽位、滑点、regime 过滤。

IC 有用的特征，完整回测经常失效：多重检验、执行摩擦看不见、regime 非平稳。长期数据把更多已 drift 的规则平均进来，反而更脏。

只有 canonical 三段、kill switch OFF 的 Phase 3 才能进入 `mlbot research close`。`verdict` 仍要人 `--declare`。

## 法庭三段是什么？Lab 记分卡为什么要摊开而不是一行？

Crypto 默认三段（`config/market_segment.yaml`）：

- **熊** `bear_2022`
- **牛** `bull_2023_2024`
- **震荡** `recent_range_to_bear`（近期高波动转熊 / 震荡，不是「再平均一次」）

主 KPI 只有五项：年化 / Calmar / WR / MaxDD / Sharpe。不要用 Total R 当头条。

一行 KPI 通常只是 DECISION 里引用的**第一次**产物（常见是 baseline / 熊）。对照变体 × 三段必须分列，否则震荡翻脸会被熊段数字盖住。Lab：`/rd` 记分卡表；本页讲「为什么」。

## Phase 1 + Phase 2 有没有在同一集合上调参又验收？会不会过拟合、过于乐观？

**会偏乐观，如果把 Phase 1+2 当成绩。** 这两步本来就不是「训练集调参 → 测试集验收」。

| 步骤 | 实际在干什么 | 和同一段历史的关系 |
|---|---|---|
| Phase 1 | 整份 `features_labeled.parquet` 上扫 IC / plateau | **发现**，全样本相关 |
| Phase 2 | 人写下 τ / lookback | **定参**，仍在同一份历史上 |
| Phase 3 | 熊 / 牛 / 震荡事件回测，KS 关 | **法庭**，日历大多还是同一段历史 |

没有经典 holdout。规则也故意不做 TimeSeriesSplit。过拟合通道是扫阈值、换条件、哪段好看留哪段，不是「系数记住训练集」。

挡法：Phase 1 不能结案；三段分列 Pareto；kill switch 关。Phase 3 换的是目标函数（年化 / Calmar / WR / MaxDD / Sharpe）和市场结构，不是未来数据。真独立样本是 A 股那种换池（core554 → full2000），不是再切一段日历当唯一考场。

## 有必要划一段 purged / embargo 做 Phase 1～3，最后一段当 OOS 吗？

**不必用「最后一段 OOS」替换现在的法庭。** Purged / embargo 只挡切点上的 label 渗漏，挡不住选错门闩。

- 最后一段往往只是一种结构（现在就是震荡 / 转熊）。用它当唯一 OOS，等于退回已否决的「只看 `recent_6m_oos`」。
- Phase 1 若看不到那段结构，会专挑趋势门闩。
- 每窗重搜 τ 的 walk-forward 是禁止的滚动 optimize。固定规则往后 replay 可以，那是监控。

想再压乐观，加的是确认后不再动的尾巴，不是替换三段：Phase 1+2 切在 `T_cut` 之前（可选：切点前空出 label 地平线 H）；Phase 3 仍跑三段 Pareto；`T_cut + H` 之后只 replay 一次，禁止回头改 τ。这条尾巴过不了 → 否；过了也不能单靠它 promote。

## 空一截是防相关，为什么还要把时间切成小块？

**防相关靠中间空一截，不是把时间切碎。** 两件事不要搅在一起。

**空一截（embargo）**  
树要先在左边拟合，再在右边打同一套分数（同一个 y，比如未来几根的收益）。`y` 本身就看未来。切在某一天、中间不空，左边最后几天的「答案」已经包含右边开头的行情，分数会被抬高。所以只在这一刀两边空出 label 那么长的时间。一刀 + 一条缝。

**切成小块（TimeSeriesSplit）**  
树容量大，整段拟合可以很好看。只留最后半年测试，你只有一个数字，而且那半年可能刚好是牛市。所以训练管线会做多次：用更早的一段拟合 → 看紧接着的下一段还行不行。小块是为了多问几次「换一段时间，这棵已经拟合好的树还在不在」，不是为了切断相关。相关仍然靠每次切的那条缝。

规则没有「先拟合、再打同一套分」，Phase 1～3 两步都不需要。按月切小块再各搜一次 τ，反而是禁止的滚动调参。规则要的是大块、冻死的门闩：熊 / 牛 / 震荡同一套都过。

## 是不是树和训练强相关？label 是 forward_rr 未来 10 根，就要 TSS + embargo + purge？

**触发条件是「拟合 + 同一套 y + 时间切」，不是「树」或「forward_rr」这两个词。**

本仓库里树走 `mlbot train`：左边拟合、右边打同一套 label 的分。所以树和这条训练切是绑在一起的。规则走扫描 → 冻死 yaml → 事件回测，没有这道切。

三件套分工：

| 工具 | 因为什么才要 | `forward_rr` 未来 10 根改什么 |
|---|---|---|
| **embargo** | 切点两边的 y 会重叠 | 缝至少 10 根（同一根 bar）；120T 就是 20 小时。树管线的 `holdout_embargo_minutes` 就是干这个 |
| **purge** | K 折里，某样本的 `[t, t+10)` 跨进另一折 | 丢掉 label 窗压到对面折的样本；H 越大，丢掉越多 |
| **TimeSeriesSplit** | 你在拟合，容量大，要多问几次「下一段还在不在」 | **不因为 H=10 才要。** H=3 也要。H 只加宽缝，不决定要不要 TSS |

所以：在训树 / 线性 / 打分器，且用会看未来的 label（`forward_rr@10`、成功标签、realized-R），**要** TSS，并且 embargo / purge 的宽度跟 H 走。  
规则 Phase 1 即使用同一个 `forward_rr@10` 算 IC，也不要这三件套当法庭——IC 不算分，法庭是三段已实现路径。  
若以后规则也做成「`T` 以前定参、`T` 以后只 replay」，那一刀上才空 H；仍然不要用最后一段替换三段法庭。

## 「删掉 label 已经踩进对面折的样本」是什么意思？

说的是这一行的**答案**已经用到了测试折里的行情。

假设 label 是「未来 10 根的涨跌」。1 号那一行的答案，看的是 1 号到 11 号的价格。现在训练折是 1～100 号，测试折从 101 号起。95 号这一行还在训练折的日历里，但它的答案用的是 95～105 号，其中 101～105 已经是测试折。训练时这道题的标准答案里已经写进了考试卷上的走势。

**踩进对面折** = 这条样本的 label 窗口 `[这一天, 这一天+H)` 和测试折的时间有重叠。  
**删掉（purge）** = 这类行不要再拿去拟合。训练折只留答案完全落在切点之前的行。

和 embargo 的差别：embargo 是两折中间再空几天，两边都不用；purge 是在已经划定的折里，把「答案跨界」的那些行划掉。一个是空一段日子，一个是删具体几行。

## SRB、fade、A 股各是什么？2h 树和 15 分钟订单流还要不要抓？

现网钱来自三件套（外加 Rolling），不是中间档的树：

| 袖套 | 定位 |
|---|---|
| **SRB** | 结构探测器（位破了再跟），择时拿趋势 beta，后面用浮盈/结构收割肥尾。不是宏观开关。 |
| **fade** | 弱质量 alpha：假动作 / 失败刺穿 + `box_pos_60` 贴边。不是经典 RSI/BB。独立 SA 账户。 |
| **A 股** | 横截面超跌：开火日 L1、8 槽等权、满 40 交易日清。 |
| **Rolling U** | 更慢的趋势体制收割（U-only）。 |

2h × 六币树（`20260831_short_term_swing_h20_court` / `20260901_…_mfe_top20`）**已 reject**：列是同期相关，没有 20 根领先。15T kline IC（`20260831_fast_scalp_15t_ic`）符号是 fade，宽池树 holdout Pearson ≈ 0；1 分钟两侧聚上去的 OF 探测也过不了门。

**不要**再扫 `tree_full` 预报 2h 路径，也**不要**把「还要抓短的」默认做成 15T 订单流树。短边若还做，必须换成交钟，并先过手续费。

## P99 大 taker 之后价格会回吐还是续走？为什么不能先假设一边？

**两边都要数，而且要切开。** 大 taker 后面叠了两台机器：临时冲击 / 库存（回吐）和信息 / 强平连锁（续走）。混成一个平均，IC 会接近 0。

成交钟事件（`20260901_btc_taker_burst_markout`，declared reject）：BTC 1 秒钟，10s 量 ≥ 过去 1h P99 且 \|失衡\|≥0.6；吸收 = 没打穿爆发前 60s 高低，位移 = 同向打穿。三月 6182 次：

- 先碰到 ±5bp：反向 54.8% / 同向 44.0%；吸收和位移几乎一样
- 同向 markout：+5s −0.38bp，+2min −0.16bp；两子集同号
- 扣 taker 往返 10bp 后两条腿都约 −10bp
- 81% 被标成位移——60s 高低对 BTC P99 太松，这一刀本身不均衡

平均路径略偏回吐，幅度远小于费。H1（切开后符号不同）/ H2（扣费后 +2min 可交易）都未过门。没跑 `event_backtest`，也不要再训 15T 树。

## 5bp 不是 VIP，他们限价还送钱。我有交易系统和返佣的话，高频是不是就是工程实现？

**5bp 是普通 taker，账没算错。高频赚的不是预报两分钟，是否定式：点差 + 返佣 − 被打穿 − 库存。**

普通 U 本位大约 maker 2bp / taker 5bp，吃单往返 10bp。BTC 永续点差经常只有 1 个 tick（约 0.1–0.2bp），零售挂单连 maker 费都不够。负 maker 是极大成交量的 VIP / 做市合同，不是把单子改成限价就出现。

你们量到的 −0.4bp，正是做市商被 P99 打穿后的 markout。他们能活，是因为毒流之前撤掉，并且大部分成交是噪声单。OMS、feature-bus、aggTrades **不是** 高频栈：缺队列位置、共置/专线、稳定排在买一卖一、以及交易所承认的负费率合同。

跨所时延才是毫秒高频。期现是资本 + 基差。8h 资金费率是持有型价差，不是高频。有返佣合同、真能排到队前、撤得过毒流，做市才变成工程问题。这三项没有时，去做高频 = 用零售费率和慢撤单去接 −0.4bp 的打穿。

更近的工程：给现有 SRB / fade 算自己成交的 markout（省滑点），或资金费率 / 期现这种持有型价差。不要为了仿高频再扫 FeatureStore。
