# 去 Top3 / 胜率是 alpha 的尺子 — 不要用它卡趋势袖套

**状态：** 方法论锁定（2026-09-07） 
**上游规则：** `.cursor/rules/strategy-classification-alpha-fattail-beta.mdc` 
**相关：** `docs/design/alpha_vs_fattail_vs_beta_CN.md`

## 0. 为什么写这一篇

`strategy-classification-alpha-fattail-beta.mdc` 已经写了「别用同一把尺子」和
「牛市去 top3 塌负 ≠ 无 alpha」。但实际操作中仍然反复出现同一个错误：

> 看到某趋势袖套 `去Top3 < 0`、`WR 40%`、`median R < 0`，就写成「收益全靠最好几笔 /
> 没有分布式 edge / 是纯肥尾」，进而给它降级、或者去「修胜率」。

这一篇补上前一条规则缺的那半边证据：**`去Top3` 的符号在很大程度上由样本量、槽位容量
和交易口径决定，而不是由信号质量决定。** 一个负的 `去Top3` 经常什么都不能证明。

## 2. 两个 `去Top3` 甚至不是同一个统计量

| 来源 | 公式 | 单位 | 交易口径 |
|---|---|---|---|
| `20260804_srb_symbol_edge_recheck/run_symbol_edge.py:113` | `ΣR − top3 R` | **R** | **只算母仓**（过滤 `is_add_position`） |
| `20260805_srb_risk_vs_add_size/run_grid.py:223` | `Σpnl_usd − top3 pnl_usd` | **USD** | **含加仓** |

跨实验直接比大小是错的。**只能在同一 n、同一单位、同一交易口径下比同族变体。**

## 3. 机制：为什么小 n / 少槽位必然让 `去Top3` 为负

1. **n=15 时去掉 3 笔 = 去掉 20% 的交易**，而且按定义去掉的正是全部右尾。
   趋势跟踪的形态本来就是「多数小亏 + 少数大赚」（上表 median R 几乎全负），
   砍掉右尾之后剩下的当然是负的。这是**算术恒等式，不是发现**。
2. **槽位容量封顶了并发持仓**。同一时刻只能开 N 个，所以已实现 PnL 天生集中在
   少数几笔上——集中度是**执行层预算的结果**，不是信号弱的证据。
3. 因此 `去Top3 < 0` 在小 n 下几乎是**必然**的，它的信息量接近零。

## 4. 锁定结论 — 禁止的用法

- **禁止**用 `去Top3 < 0` / `WR < 50%` / `median R < 0` 单独否决、降级或「修」任何
  趋势 / beta 增强 / 肥尾收割袖套（**含 SRB 与 TPC**）。
- **禁止**据此得出「收益全靠最好几笔所以没有 edge」。趋势跟踪本来就长这样。
- **禁止**把「Beta 增强」当差评。它是分类表里的**合法一类**，判据是
  「去 beta 后 alpha≈0，但回撤更浅 / 持有更稳」，不是「不合格的 alpha」。
- **禁止**为了让 `去Top3` 转正去优化胜率——那等于主动砍右尾，是本仓库
  反模式清单第一条。

## 5. `去Top3` 还能怎么正确地用

| 用途 | 合法吗 | 怎么读 |
|---|---|---|
| 同族变体、同 n、同单位下排序 | ✅ | 谁的 edge 更分布式 |
| 判断**路径依赖 / 可用性风险** | ✅ | 「如果错过最大那几笔（进程挂了、槽被占、熔断截断），这一段还剩什么」→ 这是**运维可用性指标**，应转化为 uptime / 监控要求 |
| 给袖套分类（配合中位、跨段、总R、MaxDD 一起看） | ✅ | 分类，不是评分 |
| 单独当 promote / reject 判据 | ❌ | 见 §4 |
| 跨实验比绝对值 | ❌ | 见 §2 |

## 6. 对应到具体袖套（现网）

- **SRB** = 弱 alpha + **beta 增强**（`20260727_ta_sleeve_srb_tpc/SUMMARY_SRB_TPC_VERDICT_CN.md` §4）。
  评估用尾部捕获 / MaxDD / 强平距离，**不用**胜率与去 Top3。
- **spot_accum_simple** = 肥尾收割（`20260903_spot_inventory_curve/DECISION.md`）。同上。
- **A 股超跌机械包 / 统计类中频** = 才是可以用中位与胜率评的那一类。
