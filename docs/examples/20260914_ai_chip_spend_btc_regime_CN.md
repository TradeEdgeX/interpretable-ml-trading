# AI 算力开支过多时，BTC 是不是熊

实验：[config/experiments/20260914_ai_chip_spend_btc_regime/](../../config/experiments/20260914_ai_chip_spend_btc_regime/)  
先当 **两件同时发生的市况**，不是「开支一加速，BTC 随后就会跌」。看的是：开支加速的那些日子，收盘更常在 200 日均线下面吗？不是看随后几天涨不涨，也不是看日历上这段叫不叫熊。人已经判定这句话不成立。

> AI 融资 / 算力开支过多时，BTC 处于熊或震荡，而不是随后几天涨不涨。

不是 [AI 融资公告后做多 BTC](20260914_ai_financing_btc_CN.md)，也不是 [BTC 领涨 AI 山寨](20260911_btc_lead_ai_alts_CN.md)。那两句问的是公告后或大涨后的路径；本句问的是「开支加速的日子，价格更常在均线哪一侧」。

## 这一句在本仓库里怎么走完

你对网上的 AI 说：「AI 算力开支太多的时候，现金都去买芯片了，BTC 是不是就该走熊？」

它通常会讲宏观抽水、讲随后几天涨跌。Y 若用「日历名叫熊」来当答案，2023 年反弹会被算进 2022 窗；X 若用「账单已经很大」，高强度会和日历年锁死。换一个模型，故事会换成另一家实验室。

你对本仓库说同一句。模板把题收窄：不要看随后几天涨不涨，看**同一天**收盘站在均线哪一侧。开支快不快，钉在公开芯片销售的**环比**（跟自己已经走过的中位数比，季末次日才读得到）；算不算「非牛」，看收盘有没有低于 200 日均线。日历上的熊 / 牛 / 近窗只用来分列，不当答案。这句数的是比例，不是一根根进出场赚了多少。

合并后：开支加速的日子，收盘在均线下的只有 13.4%；不够快的日子，反而是 50.5%。差 −37 个百分点，和纸上相反。2023 年账单翻倍，发生在 BTC 慢牛里。人已经判定不成立。这是两件**同时发生的市况**，不是「开支一加速，就把 BTC 按到均线下」；不能把原句翻成开空；不能和「公告后做多 BTC」并成一句。

下面七段把 X / Y 两张纸条和比例表怎么读讲完。

## 实验怎么设计的

```text
人出句（开支过多时 BTC 是熊 / 震荡，不是随后几天涨跌）
  → 先写成：开支快不快用季频账单环比；非牛用收盘是否低于 200 日均线
  → 查过：以前有没有判过同一句
  → 给每一根已收盘的日线贴两张纸条，数加速日 vs 不够快的日子谁更常在均线下
  → 人写下结不成立
```

没有「一根根进出场」的成绩单，也没有全年涨速表。先给**每一根已收盘的 BTC 日线**贴两张纸条，再数比例。独立的牛熊大约只有两段，本来就不该拿进出场年化来结案；事先写的输赢线就是这个比例，比例和纸上相反，就可以判定不成立。

| 格 | 这一句 |
|---|---|
| 机制 | 上一完整季 Epoch 芯片销售金额环比高于自身扩窗中位数时，BTC 日线收盘更常低于 200 日均线。 |
| 预期市况 | 开支加速的季对应 BTC 非牛；若加速发生在慢牛里，这句话失效。 |
| 合同 | 高强度时不许按牛市模板做多。不是开空。不加仓。闭棒。 |
| 证伪 | 高强度非牛比例 ≤ 低强度，或任一分列段反向。 |
| 落地 | 人手同一句。机器：本目录数比例。还没有按 2 小时进出场。 |

| 模板格 | 这一句怎么写 |
|---|---|
| 社会学 | 付钱的是还按 2023–24 牛市模板做多 BTC 的人。现金被抽去买加速器。 |
| 数学 | X 钉在季频环比，不用金额水平（几乎单调上升）。季末次日才可读。Y 是 MA200，不用三段标签。 |
| 统计学 | 先当 beta / 市况共存。抽样声称：高强度日非牛比例更高。 |
| 验证标准 | 比例差 ≤ 0，或任一分列段反向。不报合计 R。 |
| 数据范围 | BTC 日线闭棒 + Epoch 芯片销售 2022Q1–2026Q1。 |

## 特征

开支快不快，来自事先锁死的季频账单表；那天算不算「非牛」，用当天收盘和 200 日均线比。没有另建一套均线仓库，也没有 2 小时进出场。

### X：这天算不算「开支加速」

每个完整自然季，把 Epoch 各芯片 `Cost Estimate` 加总，得到当季美元账单。下一季才能跟上一季比，所以**环比 QoQ** 从 2022Q2 才有。

「过高」不是跟一个固定数字比，而是：这一季的 QoQ，有没有大过**截至这一季为止、所有已有 QoQ 的中位数**（至少先攒满 4 个环比才开始打标）。这叫扩窗中位数，避免用未来季来定义过去季。

季末那天的数字，要到**次日 UTC** 才允许读。2023Q2 账单再翻倍，2023-06-30 当天也还不知道；从 2023-07-01 起，后面每一根日线都背着「上一完整季 = 2023Q2、环比 +98%、高强度」这张纸条，直到 2023Q3 出炉。

前四季环比还不够打标，所以 2022 全年日线**进不了这张表**。第一根有 X 的日子是 2023-04-01（刚读到 2023Q1，+14%，标成高）。

| 可读区间（UTC） | 上一完整季 | 环比 | 高强度？ |
|---|---|---:|:---:|
| 2023-04-01 → 2023-06-30 | 2023Q1 | +14% | 高 |
| 2023-07-01 → 2023-09-30 | 2023Q2 | +98% | 高 |
| 2023-10-01 → 2023-12-31 | 2023Q3 | +55% | 高 |
| 2024-01-01 → 2024-03-31 | 2023Q4 | +27% | 高 |
| 2024-04-01 → 2024-06-30 | 2024Q1 | +56% | 高 |
| 2024-07-01 → 2024-09-30 | 2024Q2 | +21% | 低 |
| 2024-10-01 → 2024-12-31 | 2024Q3 | +21% | 低 |
| 2025-01-01 → 2025-03-31 | 2024Q4 | +22% | 高 |
| 2025-04-01 起 | 2025Q1 及以后 | +3%～+20% | 低 |

### Y：这天算不算「非牛」

Y 只有一句：这根日线收盘价有没有低于自己的 200 日均线。低于 = 非牛 = 1，否则 = 0。

三段日历 `bear_2022` / `bull_2023_2024` / `recent_range_to_bear` **不是 Y**。它们只用来把同一批日子切成三刀，看看方向会不会在某一段翻过来。2022 日历叫「熊」，并不自动把那天的 Y 记成 1；2023 日历叫「牛」，也不自动记成 0。

还要有 200 根日线才能算出均线。缺 X 或缺 Y 的日子丢掉，不进分母。

| 列 | 意思 |
|---|---|
| 范围 | 在哪一段日子上数。**合并** = 所有有 X、有 Y 的日线加在一起。 |
| 高强度非牛 | 高强度日里，收盘低于 MA200 的比例。纸上希望这个数**大**。 |
| 低强度非牛 | 低强度日里，同样比例。当对照。 |
| 差 | 高强度非牛 − 低强度非牛，单位是百分点（pp）。纸上要**正数**。0 或负数 = 证伪线被打中。 |
| n 高 / n 低 | 高强度日数 / 低强度日数。一边是 0 就不能比。 |

## IC

**这条没有收益 IC 表，也不该有。**

本句的 Y 不是「随后几天涨不涨」，而是「这一根收盘在均线哪一侧」。用窗口虚拟变量去挖次日收益 IC，会把题改回 [融资公告句](20260914_ai_financing_btc_CN.md)。

若把「环比」当连续分数、对次日收益算 Spearman，那是另一句。本页的探照灯就是比例表本身：高强度日非牛该更多。它不是五项 KPI，也不能改成开空合同。

## 验证

尺子事先写在纸上：高强度非牛比例 **≤** 低强度，或任一分列段反向，原句就死。

举例：合并行「13.4% / 50.5% / −37.1pp / 546 / 610」读成：

- 有 X、有 Y 的日线一共 546 + 610 = 1156 根。
- 546 根背上「上一季环比过高」：其中 **73** 根收在 MA200 下（13.4%）。
- 610 根背上「上一季环比不够高」：其中 **308** 根收在 MA200 下（50.5%）。
- 开支加速的日子，非牛比例反而低了 37 个百分点。

| 范围 | 高强度非牛 | 低强度非牛 | 差 | n 高 / n 低 |
|---|---:|---:|---:|---:|
| 合并 | 13.4% | 50.5% | **−37.1pp** | 546 / 610 |
| `bear_2022` | 27.7% | 无样本 | — | 213 / 0 |
| `bull_2023_2024` | 14.9% | 39.7% | **−24.8pp** | 396 / 184 |
| `recent_range_to_bear` | 15.6% | 55.1% | **−39.5pp** | 90 / 425 |

| 范围 | 怎么读 |
|---|---|
| 合并 | 全样本已经反向：加速日里 BTC 更常站在 MA200 **上**。纸上说加速日该更常在均线 **下**。 |
| `bear_2022`（2022-01-01 → 2023-11-01，只分列） | 2022 年还没有「过高」标签。窗里真正进表的，是 2023-04-01 到 2023-10-31，大约 213 根，背上的全是 2023Q1–Q3，三季都是高。低强度日 = 0，差没法算。日历名叫熊，但这段能测的日子已经是 2023 年反弹；213 根里只有 27.7% 还在 MA200 下。不能用「熊段也是高」给原句加油。 |
| `bull_2023_2024` | 高强度大多是 2023 年中到 2024 年中账单连续翻倍的那些季，396 根里只有 14.9% 在均线下。低强度是 2024 年下半年环比降回中位数附近的 184 根，非牛 39.7%。差 −24.8pp，和纸上相反。 |
| `recent_range_to_bear` | 高强度只剩 2024Q4 那一张纸条（2025 年 1–3 月，90 根），非牛 15.6%。2025Q1 起环比都标低（425 根），非牛 55.1%。差 −39.5pp，还是反向：后来账单还在变大，但**涨速**下来了，BTC 反而更常掉到均线下。 |

三段里凡是两边都有样本的，符号都和声称相反。证伪线打中。

## 结论

2023 年芯片账单从约 32 亿翻到约 126 亿，同一段日历里 BTC 走出减半前后的慢牛，收盘大部分时间在 MA200 上方。纸上把「实验室在付加速器账单」读成「现金从币圈抽走、BTC 该非牛」；本机看到的是两件**同时发生的市况**，不是「开支加速 → 把 BTC 按到均线下」。

2025 年以后账单水平更高，环比却回到扩窗中位数以下，BTC 低于 MA200 的日子反而更多。这更像同一段风险偏好周期里的共存，不是可交易的先后关系。

分类：**beta / 市况共存**。机器不按「开支加速就不要做多 BTC」跑，人也不按这句手做。人已经判定不成立。

## 报告解读

1. **这不是年化表。** 13.4% 是「这类日子收在均线下的比例」，不是收益，也不是五项 KPI。不要把它读成「高强度亏 13%」。
2. **差必须对两边都有 n 的行。** `bear_2022` 的 n 低 = 0，这一行不能当「熊段也支持原句」。
3. **日历名不是 Y。** 2022 窗叫熊，进表的却是 2023 年反弹。2023 窗叫牛，Y 仍按 MA200 逐日算。
4. **水平 ≠ 环比。** 2025 年账单更大，但环比标低，非牛反而更多。原句锁的是涨速，不能事后改成「账单已经很大」。
5. **扩窗中位数没有未来。** 2023Q1 的「高」只用到当时已有的环比。不要用全样本中位数重标定历史。
6. **季末次日才可读。** 2023-06-30 不能用 2023Q2 的 +98%。若扫描把当季当天打上高，表作废。
7. **不要改成开空。** 合同写的是「高强度时不许按牛市模板做多」，不是开空。比例反向也不能把原句翻面。
8. **和融资公告句不要并表。** 那句的 X 是 21 笔日历事件，Y 是随后 5 日收益。本句的 X 是每个交易日背上的上一季环比。
