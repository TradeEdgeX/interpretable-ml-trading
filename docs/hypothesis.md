# 验证假设

**English:** [hypothesis.en.md](hypothesis.en.md)

人平时不用读这一页，跟本仓库里的 AI 说话就行（见 [README_CN.md](../README_CN.md)）。  
这一页是给 AI 的：怎么把用户的一句话收成能验证对错的几条。

量化回测和手写清单走同一句话。差别只在谁执行。

---

## 1. 一句话循环

```text
人写出假设
  → AI 帮你写成可登记的特征、规则、清单（不改你的命题）
  → 程序用事先定好的回测来量（收盘才知道的数字、至少三段日子、比策略时关掉账户保护）
  → 人写下结论：成立、不成立、还要更多证据
  → 成立：写进规则文件，或写成手做清单
     不成立：机器不跑，人也不许用手做同一句
```

主循环不是「尽快挖出更多分数」。主循环是看完表之后，判定这句话成不成立。

和「AI 过夜挖因子、相关一涨就当下一轮基线」相反。那边优化的是分数；这边优化的是**一句话还成不成立**。

---

## 2. 同一句，两种落地

假设不是策略名，是一句带机制的话。例如：

> 价格在 50 日均线上、且刚上穿 200 日均线时做多，跌破 50 就走。  
> 我预期这在趋势年赚钱，在震荡年不亏太多。  
> 若震荡年回撤更深，或折合成一年是亏的，这句话就不成立。

| 落地 | 怎么用这句 |
|---|---|
| **量化** | 写成 `ma_cross` 一类规则文件：什么时候允许做、往哪边、做错了怎么走、仓位多少。回测算出五项数字。 |
| **手动** | 写成清单：今天许不许做、进场条件、出场价、不许摊、到点才动。到点执行，不讨论。 |

回测判定不成立，对两种落地效力相同：**这句不能当钱用。**  
不要回测已经说明不成立，晚上再手做「感觉这回不一样」。

判定「还可以用」，只表示：在事先约定的尺子上，这句还没有被数字打穿。  
它不是「今晚满仓」。机器人按规则文件跑；人按清单跑。都不再现场发明第三种做法。

## 3. 先填模板，再写五格，再量

本仓库是假设验证器。空五格看起来像策略说明书；要先写清这是哪种社会、数学、统计现象，以及用哪把尺子、哪段数据判定不成立。

完整格子、AI 怎么验、验完怎么编排：[hypothesis_template.md](hypothesis_template.md)。

没写完模板，不要下数据、不要回测。

```text
原句        人说的那一句（AI 不改题）
社会学      谁付钱、什么群体行为会重复
数学        测量对象 + 闭棒
统计学      抽样声称 + 先分类（alpha / 肥尾 / beta / 无用）
验证标准    哪一段、哪一项数字坏了就不成立
数据范围    品种、周期、事先定好的三段日子
五格        机制 / 市况 / 合同 / 怎样算不成立 / 落地（可执行的同一句）
```

AI 先跑结构校验（齐不齐、和教训冲不冲），**不是**用记忆判断真假：

```bash
mlbot research validate <id>
mlbot research index --trusted --query <english-slug>
```

模板不过 → 只改纸面。命中已结案 → 复述判决，停下。  
**禁止**把你的句子偷换成附近一条现成规则（均线交叉 ≠ 远离均线死区 ≠ 结构突破）。

## 4. 特征发现（测量，不是挖分）

新列必须能回答假设里的一个词。例如「刚上穿」需要交叉事件，「离出场还有多远」需要均线距离。

1. 给事件起名（人）。
2. 写成 FeatureStore 可算的列，登记 `config/feature_dependencies.yaml`。
3. 闭棒：开盘索引的行，只在收盘后可知。见 [math.md](math.md) §1。
4. 缺列先 backfill，不要在回测里现场 `compute_*`。

特征是**测量**。进 / 止 / 加 / 出是**合同**，写在 YAML 或清单里。  
不要把十个测量叠成一个分数，再把分数当成更强的假设。

自动组合搜索（IC 爬山、特征组搜索）只许当 Phase 1 探照灯：帮人看到「这句话在哪类场景像死了」。  
分数涨了不能结案，不能改 locked 规则。详见 [design/2026-08-23_human_hypothesis_vs_auto_mine_CN.md](design/2026-08-23_human_hypothesis_vs_auto_mine_CN.md)。

## 5. 「训练」在这里指什么

本树**不用**模型拟合当结案。没有 `mlbot train`，没有把 TimeSeriesSplit 平均分当成判决。

这里的训练是把尺子校准到可复现：

| 步骤 | 做什么 | 不是 |
|---|---|---|
| FeatureStore | 按月算列，闭棒 | 拟合预测器 |
| Phase 1 扫描 | 看这句话在标签上亮不亮、高原在哪 | 结案 |
| 回测 | 熊市、牛市、最近这段各跑一遍，比策略时关掉账户保护 | 调参到顺眼 |

过拟合的通道不是「几千个系数记住了 2022-05-13」，是「扫阈值、换条件、留下好看的窗」。  
挡法：假设事先写清楚、三段日子分开报、坏一段就否、账户保护不得用来藏回撤。问答：[agent/rd_qa.yaml](agent/rd_qa.yaml)。

## 6. 怎么量

人说「量这句」之后才启动。只想把框架写清楚时，建目录就停。

```bash
mlbot research init 20260910_<slug> --strategy ma_cross
mlbot research run 20260910_<slug>
mlbot research close 20260910_<slug>
mlbot research close 20260910_<slug> --declare reject   # 人写 verdict
```

| 必须 | 原因 |
|---|---|
| 对口 harness（公开 dummy = `event_backtest` / `ma_cross`） | 换评测机 = 换题 |
| 熊市、牛市、最近这段，至少三段 | 合成一段会把坏年洗掉 |
| 比策略时关掉账户保护 | 各变体停在不同时刻，好坏不可比 |
| 五项数字：折合成一年、Calmar、胜率、最大回撤、Sharpe | 不要用合计盈亏当头条 |

先分类再拧旋钮：这句话是 alpha、肥尾收割、beta 增强，还是无用。尺子不同。  
[design/alpha_vs_fattail_vs_beta_CN.md](design/alpha_vs_fattail_vs_beta_CN.md)

完整命令：[usage.md](usage.md)。谁写数字、谁宣判：[agent/rd_playbook.md](agent/rd_playbook.md)。

## 7. 判决怎么用在手上

| `verdict` | 机器人 | 人 |
|---|---|---|
| `reject` | 不写入 YAML | **不做这句。** 不是「减半再试」「换个标的再试」 |
| `park` / `needs-more` | 不部署 | 不下手。缺的是证据，不是勇气 |
| `promote` | 按锁定的规则文件跑 | 按同一句清单跑：许可、出场、时钟。到点执行 |

手做清单最少四格，和 YAML 对齐：

1. **许可** — 今天这类行情许不许做（慢变量 / 大位置）
2. **进场** — 主信号在不在（不要用数学噪声分代替结构）
3. **出场** — 价到了无条件结束。改出口 = 新开一笔，重走验证
4. **时钟** — 没到点不加、不换、不「再看看」

验证框架能指导手动，是因为它**拿走临场发明**。它不能代替你去盯盘找感觉。

---

## 8. 不要把它做成

- 自动挖因子、分数停了就上线
- 用交叉验证平均分代替三段判决
- 只看最近半年
- 回测否了，手做同一句
- 判决成立后，现场加一个没验过的止盈/摊平
- 把本树说成「可解释的机器学习交易机器人」

## 9. 已量例子怎么读

`docs/examples/` 里每一篇都先讲**故事**（网上的 AI 会说什么、你对本仓库说同一句之后必须走哪几步），再按七段写完，能用表格的地方都用表格。AI 复述数字、人写下结论时，按这个顺序，不要跳到「折合成一年是正的」。

| 段 | 作用 |
|---|---|
| 实验怎么设计的 | 用哪种回测、五格、怎样算不成立，事先写清楚 |
| 数据 | 品种、周期、分窗、缺年写无样本 |
| 特征 | 列从哪来、收盘才知道的数字第二天怎么用 |
| 相关扫描 | 有则只当探照灯；无则写清为什么不该有 |
| 验证 | 对照 + 五项数字（或该回测自己的尺子） |
| 结论 | 先说钱从哪来；人自己写下成不成立 |
| 报告解读 | 标题是折合成一年，不是合计盈亏；对照不能换；最近这段不能单独过关 |
