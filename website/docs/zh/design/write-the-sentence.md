# 填模板

把一句交易想法写成能验证对错的合同，从填写 `docs/hypothesis_template.md` 的五格开始。已经量过的例子都是同一条路：网上的 AI 会讲什么故事 → 本仓库必须先填模板、查以前有没有判过同一句 → 你对本仓库里的 AI 说「测试一下这个策略」之后，它才下载数据 → 程序算出一张表 → 你读表后写下结不成立。填完之后再读七段：实验怎么设计的、数据、特征、相关只用来照亮、验证、结论、报告怎么读。

## 五格（写进 `DECISION.md`）

| 格 | 写什么 | 例子（均线金叉） |
|---|---|---|
| 机制 | 这句话为什么能赚钱、发生了什么才允许做 | 趋势继续走：收盘在 50 日线上方，并且刚上穿 200 日线，才允许买入 |
| 预期市况 | 哪段行情应该赚、哪段应该亏或失效 | 趋势段该赚；震荡段回撤不该更深；折合成一年不该变亏 |
| 合同 | 什么时候进、往哪边、什么时候出；加不加仓；账户保护开不开 | 跌破 50 日线就走；不加仓；账户保护关掉；收盘才知道，第二天才能用 |
| 怎样算不成立 | 哪段日子、哪一项数字坏了，这句话就不成立 | 任意一段折合成一年是亏的，或震荡段回撤深于趋势段 |
| 落地 | 用哪一种回测；机器和人手是不是同一句话 | 一根品种进出场 + 对应的特征层；人手同一句 |

只填这五格，看起来还像策略说明书。你还要先写清：这是哪种社会、数学、统计现象，以及用哪段数据判定它不成立。完整格子在 [假设模板](https://github.com/TradeEdgeX/interpretable-ml-trading/blob/main/docs/hypothesis_template.md)。

## 量完之后，报告按七段读

| 段 | 你要能回答 |
|---|---|
| 实验怎么设计的 | 比的是一根品种进出场、每天给全市场打分，还是一季一季拿满年数？五格和「怎样算不成立」事先写了吗？ |
| 数据 | 品种、周期、来源、三段日子的起止。缺的年份写了「没有样本」吗？有没有套错市场的日历？ |
| 特征 | 列是从事先算好的库里读的吗？开盘是不是只读上一根？有没有在出成绩时现场另算？ |
| 相关（只用来照亮） | 有表的话，它不能单独下结论。没有表的话，是不是一根品种的开关信号，本来就不该有这张表？ |
| 验证 | 对照是现金、「每人买一点」，还是同一段日子一直拿着？相对差有没有碰到事先写的标准？ |
| 结论 | 先分类（多出来的本事 / 少数狠行情 / 跟着市场走 / 无用）。由人写下结不成立，不要手写结论栏。 |
| 报告怎么读 | 标题是折合成一年，不是把每笔盈亏加总；胜率高不等于跟上了牛市；回撤变浅可以是保险；最近这段不能单独过关。 |

对照一篇已经写完的七段：[买 ETF 会错过美股牛市吗](https://github.com/TradeEdgeX/interpretable-ml-trading/blob/main/docs/examples/20260914_eq_us_spy_qqq_beta_CN.md)。全部已量过的句子在 [已量展厅](../gallery/index.md)。

## 填完之后

把填好的模板交给本仓库里的 AI，让它帮你写成程序能跑的规则、跑回测、印出表。你读表，对照事先写好的标准，自己写下结不成立。在你说「测试一下这个策略」之前，AI 只许检查模板齐不齐、以前有没有判过同一句、建好目录，不许下载，也不许回测。
